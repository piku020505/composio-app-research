The patterns (headline)
  1. Auth is a two-horse race: OAuth2 and API keys. 75 apps support OAuth2 and 80 accept a static key or token; the primary method is OAuth2 for 48 apps. A toolkit platform that does OAuth2 + key-in-header well covers nearly everything; the exotic cases (HMAC signatures, OAuth 1.0a, KYC'd exchange keys) are a handful.
  2. Access, not technology, is the bottleneck. 98 of 100 have a documented public API, but 24 can't be self-served (no free or trial credentials), and 34 more carry friction such as app review, rate-limited unreviewed apps or a runtime wrapper. The most common blocker is Paid plan required (13 apps), followed by app review/approval and partner or customer-only gates.
  3. Self-serve follows the buyer. Developer-facing categories are open: Developer, Infra and Data platforms (10/10) and CRM and Sales (9/10) are the most self-serve. Gates cluster where money, ads spend or regulated data moves: Ecommerce (5/10 self-serve) and AI, Research and Media-native (6/10), while Finance has the fewest apps ready today (2/10), because customer-only accounts, KYC and production approval dominate.
  4. MCP is already table stakes. 96 of 100 apps have an MCP server today (80 official). Caveat: several "official" MCPs only search the vendor's docs or cover developer tooling rather than the product's data (e.g. Twilio, Shopify Dev MCP, Adobe), and many need a paid plan. So Composio's edge isn't "an MCP exists". It's managed auth, consistent and tested action schemas, and covering the 16 apps served only by community servers plus the 4 with none.
  5. Easy wins vs outreach. 60 apps are buildable today with self-serve credentials. 5 of those have no official MCP (community-only or none), which makes them the quickest differentiated wins. 12 need a human to apply, pass review or sign a partner deal, and 14 need a paid plan just to get a test account (a budget call, not an engineering one).

The agent: what I built and where a human was needed

1 · SpecOne schema plus allowed values (RESEARCH_SPEC.md). Every field must cite a URL, and the agent writes "low confidence" rather than guess.
→
2 · Research (×10 parallel)One LLM agent per category, with web search + fetch. It reads official auth, credential and API docs and searches for MCP servers.
→
3 · Loop 1: validatorvalidate.py checks the schema, allowed values and contradictions ("gated but ready", MCP without URL, missing evidence). It flagged 29/100.
→
4 · Loop 2: gap-fill agentsEvery flagged record was re-researched from scratch. Unresolved apps went from 24 to 0.
→
5 · Loop 3: auditor agentA separate agent with no stake in the answers re-opened the evidence for a random 20 apps × 5 fields, and wrong fields were corrected.
→
6 · HumanHuman: defined the spec and verdict rules, ruled on the auditor's disputed calls (table below), and reviewed edge cases such as "does a trial count as self-serve?".

Runnable: python3 agent/research_agent.py --ids 1-100 --out research/pass1/run.json (Anthropic API + server-side web search/fetch), then validate.py → research_agent.py --recheck → build.py. See the README. The published dataset was produced by the same spec and loops, orchestrated as parallel Claude agents.

Constraints and honesty: where it struggled

  • Search budget. The first pass hit a shared web-search cap, so about a quarter of apps came back "unknown". The validator caught every one, and they were re-researched in loop 2. That's why the "round 2" tag appears in the table.
  • Obscure apps. Paygent Connect, iPayX and fanbasis have little or no public developer documentation. Where the evidence is thin, the record says so and carries low confidence rather than guessing.
  • Gated docs. Several vendors (e.g. PitchBook, Salesforce Commerce Cloud, Brex/Ramp) only show API docs or credentials to customers. Per the brief, "gated, with evidence" is the finding, not a failure.
  • Docs drift. Plans and gates change often (Google Ads retired developer tokens on 2026-09-09; Zendesk is sunsetting API tokens). Each row cites what the docs said on 2026-11-23.
  • Self-serve trial vs free is a judgement call. I count a free trial with working API access as self-serve, but separate it so it can be filtered out.
